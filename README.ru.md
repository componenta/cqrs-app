# Componenta CQRS App

`componenta/cqrs-app` находит обработчики и слушателей по атрибутам и сохраняет их регистрации в артефакте общей сборки приложения. Шины команд и запросов, локаторы и метаданные предоставляет [componenta/cqrs](https://github.com/componenta/cqrs).

## Установка

```bash
composer require componenta/cqrs-app
```

Для CQRS App 6 требуются PHP 8.5.13+, App 6, Config 4, DI 6 и CQRS 5. Class Finder предоставляет общий итератор классов, Tokenizer — сведения о классах. Для команды `app:build` установите App Console 6.

Порядок провайдеров:

```php
return [
    new \Componenta\App\ConfigProvider(),
    new \Componenta\App\Console\ConfigProvider(),
    new \Componenta\CQRS\ConfigProvider(),
    new \Componenta\CQRS\App\ConfigProvider(),
    new ApplicationConfigProvider(),
];
```

Провайдеры могут подключаться существующим списком, созданным Composer. Пути поиска классов задаются обычными средствами App. App предоставляет ленивый исходный итератор через `Componenta\App\ConfigKey::DISCOVERY_SOURCE` (`app.discovery.source`).

## Обработчики и слушатели

```php
use Componenta\CQRS\Command\Attribute\AsCommandHandler;

final readonly class PublishPost
{
    public function __construct(public int $id) {}
}

#[AsCommandHandler]
final class PublishPostHandler
{
    public function __invoke(PublishPost $command): string
    {
        return 'published:' . $command->id;
    }
}
```

Для обработчиков запросов используется `AsQueryHandler`. Атрибут обработчика объявляется на классе или на его публичном нестатическом методе. Атрибут класса выбирает `__invoke()`, а при его отсутствии — `handle()`. Тип первого параметра определяет сообщение, если имя не задано явно в атрибуте. Дополнительные обязательные аргументы при вызове обработчика через DI не разрешаются.

Слушатели реализуют `CommandListenerInterface`:

```php
use Componenta\CQRS\Command\Attribute\AsCommandListener;
use Componenta\CQRS\Command\Event\CommandFailedEvent;
use Componenta\CQRS\Command\Event\CommandListenerInterface;
use Componenta\CQRS\Command\Event\CommandProcessedEvent;
use Componenta\CQRS\Command\Event\CommandProcessEvent;

#[AsCommandListener(PublishPost::class, priority: 10, eventTypes: [CommandProcessedEvent::class])]
final class PublishPostListener implements CommandListenerInterface
{
    public function handleEvent(CommandProcessEvent|CommandProcessedEvent|CommandFailedEvent $event): void
    {
        // Реакция на успешную публикацию.
    }
}
```

Для отправки событий добавьте `Componenta\CQRS\Command\Middleware\EventMiddleware::class` в `Componenta\CQRS\ConfigKey::COMMAND_MIDDLEWARES`. Зависимости обработчиков и слушателей задаются обычными фабриками DI или разрешаются автосвязыванием.

Явные регистрации добавляются в списки ядра `cqrs.command_handlers`, `cqrs.query_handlers`, `cqrs.command_listeners`. Одинаковые явные и найденные регистрации объединяются. Разные обработчики одного сообщения вызывают исключение. Повтор одинакового атрибута слушателя объединяется; повтор одинаковой явной регистрации слушателя вызывает исключение. Порядок слушателей: приоритет по убыванию, затем идентификатор сервиса и канонический список событий.

## Загрузка и сборка

Провайдер регистрирует три фабрики:

| Сервис | Назначение |
|---|---|
| `cqrs.maps` | Общие массивы для фабрик локаторов ядра. |
| `CqrsDiscoveryIndex` | Ленивое извлечение всех трёх секций за один проход. Конкурентное или рекурсивное обращение во время обхода вызывает `LogicException`, не меняя состояние текущего обхода. |
| `CqrsBuilder` | Участник сборки из списка `app.builders`, записывающий полный результат из исходников. |

`CqrsBuilder` записывает артефакт `cqrs.maps` с версией схемы 1. Каталог сборки, сериализация, манифест поколения и публикация принадлежат App. Отдельного пути вывода у пакета нет.

```bash
php bin/console.php app:build
```

Обычная консольная команда заново составляет конфигурацию из исходников и создаёт контейнер для сборки независимо от снимка, выбранного работающим приложением. Просмотр списка команд и справки не создаёт участников сборки и не запускает поиск классов ради подготовки артефактов. Конструктор `CqrsBuilder` только сохраняет исходные зависимости.

`CqrsBuilder::build(BuildContext $build)` получает исходный индекс и явные регистрации и передаёт полную нормализованную карту в `BuildContext::write()`. Уже выбранная карта работающего приложения не используется как источник сборки. App публикует поколение целиком только после успешного завершения всех участников. Ошибка исходных данных, регистраций или записи оставляет выбранным предыдущее поколение; частичная карта CQRS не публикуется.

Полезная нагрузка артефакта содержит ровно три секции:

```php
return [
    'command_handlers' => [],
    'query_handlers' => [],
    'command_listeners' => [],
];
```

При первом получении локатора общая фабрика `cqrs.maps` проверяет явную конфигурацию и читает свой артефакт из `PreparedBuild`, выбранного App. Для проверки наличия снимка используется идентификатор `Componenta\App\ConfigKey::PREPARED_BUILD`: проверка класса недостаточна в контейнере с автосвязыванием. Если необязательный артефакт отсутствует, пропущен при сборке, несовместим или некорректен, используются исходный индекс и явные регистрации. `APP_DISCOVERY_SOURCE=1` переключает загрузку на исходники. Ошибки конфигурации и исходных регистраций выходят наружу. Во время работы приложения каталоги и файлы не создаются, участник сборки не вызывается.

Корректная подготовленная карта содержит полный снимок регистраций. Текущие явные регистрации проверяются, но не добавляются поверх снимка. После изменения регистраций нужна пересборка. Экземпляры обработчиков команд и запросов по-прежнему разрешаются через текущий контейнер.

Правила одинаковы во всех окружениях. Актуальный артефакт позволяет пропустить поиск классов, сохраняя выбор обработчиков, порядок слушателей и ошибки исходных регистраций. После изменения исходников или конфигурации пересоберите приложение либо выполните `app:clean` и перезапустите долгоживущие процессы. Код, конфигурация и поколение сборки публикуются как согласованный выпуск. App может привязать снимок к явно заданному `APP_BUILD_ID`. Очистка снимает публикацию для новых запусков; уже выбранные поколения остаются доступны существующим читателям. Структурно корректный, но устаревший артефакт не выявляется повторным обходом исходников во время работы приложения.

## Метаданные

Стандартный `ReflectionCommandMetadataProvider` ядра создаёт свежие атрибуты по запросу, в том числе для команд без регистрации обработчика. Участник сборки записывает только регистрации обработчиков и слушателей. Метаданные повторных попыток, блокировок и транспортов читаются при выполнении команды.

## Переход на новый API

Замените версионную карту `cqrs.map` и скомпилированную конфигурацию CQRS явными списками регистраций. Удалите `cqrs.map_file` и обращения к `Componenta\CQRS\App\ConfigKey`: пакет больше не задаёт путь к файлу. Вместо `CqrsMap` и его провайдеров используются обычные массивы либо общий сервис `cqrs.maps`. Удалите регистрацию классов метаданных и вызовы `isKnown()`. Собственные фабрики локаторов переведите на массивы, как показано в документации ядра.

При публикации удалите прежний самостоятельный артефакт CQRS и выполните `app:build` для соответствующих кода и конфигурации. `CqrsBuilder` больше не принимает имя файла, а его метод `build()` требует общий `BuildContext`. Отдельная очистка CQRS удалена; используйте хранилище сборки приложения или `app:clean`.

## Интеграционные тесты

Сквозной набор использует рабочие копии App, Config, DI, CQRS и его расширений из соседних каталогов. Он проверяет загрузку этих копий через Composer, обычную команду сборки приложения, а также транспорты, политики доступа, повторные попытки, блокировки и транзакции с исходными и подготовленными картами. SQLite работает в памяти.

Разместите репозитории зависимостей рядом с этим пакетом и выполните:

```bash
composer --working-dir=integration install
composer test:integration
```

Нужны PHP 8.5.13 или новее и расширения `pdo_sqlite`, `mbstring`. Версии локальных пакетов в `integration/composer.json` задают целевой набор совместимости; до публикации соответствующих версий используйте их согласованные ветки рефакторинга. Набор требует CQRS Policy 4.1, CQRS Transport 5.1, CQRS Transaction Cycle 3.1, а также ветки Retry 4, Lock 4 и Policy 4. Ранее опубликованные расширения с ограничениями до Config 3 или CQRS 4 этому набору не соответствуют.
